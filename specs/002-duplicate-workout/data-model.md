# Data Model: Duplicate Workout

This feature introduces no new entities and no schema version change. A duplicate is an ordinary
Workout record in `state.workouts`. The sections below document the updated constraint and the
new domain operation.

## Updated Constraint: Workout Name Length

- `name`: trimmed string, **1–50 characters** (updated from 60; see `research.md` Decision 4)

All other Workout, Planned Exercise, Session, Set Result, and Planner State definitions remain
as documented in `specs/001-gym-session-planner/data-model.md`.

## Duplicate Operation

`duplicateWorkout(state, workoutId, options?)` → `{ state, workout }`

### Pre-conditions

- `workoutId` must match an existing Workout in `state.workouts`.

### Post-conditions

- A new Workout is appended to `state.workouts` with:
  - A new unique `id` (generated by `makeId()`).
  - A `name` derived by the default name algorithm (see below).
  - `exercises`: a deep copy of the source's Planned Exercise list (same order, same
    `exerciseId`, `sets`, and `targetReps`).
  - `createdAt` and `updatedAt` set to the current timestamp (`options.now` if supplied).
- The source Workout is not modified.
- No existing Workout, active Session, or history entry is affected.

### Default Name Algorithm

```
candidate ← "Copy of " + source.name, truncated to 50 characters
existing  ← { w.name | w ∈ state.workouts }
if candidate ∉ existing → use candidate
else for n = 2, 3, 4, … :
  candidate ← ("Copy of " + source.name + " (" + n + ")"), truncated to 50 characters
  if candidate ∉ existing → use candidate
```

The suffix is appended to the full string before truncation, so the 50-character limit is always
respected regardless of the source name length.

### Error Conditions

- Throws `Error("Workout not found.")` if `workoutId` does not match any Workout in state.
